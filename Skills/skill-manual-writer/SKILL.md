# Skill Manual Writer

為任意 Claude Skill 產出一份結構完整、技術精確的 `manual.md`，讓團隊成員不需要看原始碼就能理解這個 skill 的設計理念、工作原理與使用方式，也讓未來維護者清楚知道哪裡可以擴充或修改。

---

## Step 1：取得目標 Skill 路徑

先確認使用者要文件化的 skill 位置。如果使用者沒有提供路徑，詢問：

> 「請提供 skill 的路徑（例如 `Skills/ado-devops`）或直接告訴我 skill 名稱，我會協助找到對應目錄。」

若只提供名稱，用 Glob 工具搜尋：`**/SKILL.md`，找到對應的 skill 目錄。

---

## Step 2：讀取所有 Skill 資產

找到 skill 目錄後，系統性地讀取全部內容：

```
<skill-dir>/
├── SKILL.md              ← 必讀，核心邏輯與觸發條件
├── scripts/              ← 讀取所有 .py / .sh / .js 等腳本（若存在）
├── references/           ← 讀取所有參考文件（若存在）
├── agents/               ← 讀取所有 subagent 指令（若存在）
├── helpers/              ← 讀取輔助文件（若存在）
├── assets/               ← 列出但不讀取二進位資產
└── prompts/              ← 讀取 prompt 模板（若存在）
```

**讀取策略**：
- SKILL.md 全文讀取
- 腳本檔案：讀取前 80 行 + 函式/指令列表（grep `^def ` 或 `^function `）
- 長文件（>300 行）：讀取前 50 行 + 目錄結構（若有）
- 列出所有檔案並記錄每個檔案的用途推斷

---

## Step 3：分析 Skill 結構

讀取完成後，在內部整理以下資訊（不需要輸出，只是分析用）：

| 分析面向 | 要找的內容 |
|---------|-----------|
| **目的** | 這個 skill 解決什麼問題？針對什麼使用者？ |
| **觸發條件** | description 欄位裡的觸發情境 |
| **執行步驟** | SKILL.md 中的主要工作流程（有幾個階段？） |
| **元件依賴** | 哪些腳本呼叫哪些腳本？外部 API/工具有哪些？ |
| **輸入輸出** | 需要什麼 env vars / 參數？產出什麼？ |
| **邊界條件** | 錯誤處理、限制、已知問題 |

---

## Step 4：生成 manual.md

在 skill 目錄下建立 `manual.md`，使用以下模板。根據 skill 實際內容填寫，不要填寫佔位符或「N/A」——若某個段落真的不適用，直接省略該段落。

## Step 5：回報與輸出

manual.md 寫入完成後，告知使用者：

1. 產出的檔案路徑
2. 文件包含哪些段落（用清單列出）
3. 如果有任何資訊無法從現有檔案推斷（例如「設計決策」可能需要原作者補充），明確標示哪些部分需要人工補充

**輸出格式要求**：

- **語言**：根據 SKILL.md 的語言決定——若原 skill 主要是繁體中文，manual.md 使用繁體中文；若是英文，使用英文。混合語言的 skill 使用繁體中文為主。
- **ASCII 圖表**：必須使用 box-drawing 字元（`┌ ─ ┐ │ └ ┘ ├ ┤ ┬ ┴ ┼ →`）讓圖表在等寬字型中正確對齊
- **程式碼區塊**：所有指令都必須包在 \`\`\` 區塊內，並標注語言（bash、python、yaml 等）
- **表格**：優先用表格整理有多個欄位的資訊（檔案清單、指令列表、錯誤對照）

## 品質檢查清單

manual.md 產出後，自我檢查：

- [ ] 架構圖是否正確反映 skill 的目錄結構與元件關係？
- [ ] 執行流程圖是否完整涵蓋主要路徑（含錯誤路徑）？
- [ ] 每個腳本/元件是否都有說明？
- [ ] 使用範例是否有真實的指令或觸發語句（不是抽象描述）？
- [ ] 開發者指南是否說明了擴充點？
- [ ] ASCII 圖表在等寬字型下是否對齊？
- [ ] 是否標記了需要人工補充的段落？
