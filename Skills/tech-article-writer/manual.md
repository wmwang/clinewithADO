## 技能概覽

| 欄位 | 說明 |
|------|------|
| **技能名稱** | `tech-article-writer` |
| **觸發關鍵字** | 「寫科技文章」、「AI 教學文」、「技術導入指南」、「內部技術通訊」、「幫我寫一篇關於 XXX 的文章（科技/AI 主題）」 |
| **主要功能** | 根據指定主題，撰寫 1000–2000 字的繁體中文企業內部科技文章；支援 Markdown 與 HTML 雙格式輸出 |
| **前置條件** | 無需額外 env vars 或外部服務；使用者需提供文章主題 |
| **產出物** | `.md` 文章檔案（預設）；選擇性同時產出 `.html` 檔案 |
| **技術依賴** | 純 Claude 文字生成，無外部 API 呼叫；HTML 輸出使用內嵌 CSS |

### 這個 Skill 做什麼

`tech-article-writer` 是一個針對企業內部溝通場景設計的文章生成 skill。它的目標讀者是背景多元的同事——從資深工程師到完全不懂 AI 的業務人員——因此文章風格強調「不失專業、容易理解」，語調像在茶水間跟同事說話，而非學術論文腔。

這個 skill 內建了三種常見的企業科技文章類型：**AI 工具教學**（從具體場景切入、給出操作步驟）、**技術導入指南**（比較導入前後差異、列出前置條件）、以及**科技概念科普**（解釋術語、讓非技術同事看懂）。每種類型都有對應的寫作提示，讓 Claude 能根據主題自動選擇合適的切入角度。

輸出格式方面，skill 預設產出 Markdown，也能在使用者要求下產出 HTML。HTML 版本包含完整的內嵌 CSS：sans-serif 字體、1.8 行距、表格交替行底色、最大寬度 800px 置中顯示，以及響應式設計，確保手機也能閱讀。

## 元件說明

### 檔案清單

| 檔案 | 類型 | 功能說明 |
|------|------|---------|
| `SKILL.md` | 指令文件 | Claude 的完整執行指引：寫作原則、文章模板、輸出格式規範、常見主題寫作提示、品質檢查清單 |
| `evals/evals.json` | 評測資料 | 3 個評測案例，用於驗證 skill 在不同文章類型（導入指南、工具教學、概念科普）下的輸出品質 |

### 核心文件說明

#### `SKILL.md`

**功能**：定義 Claude 生成科技文章的完整行為規範。

**主要章節**：

| 章節 | 說明 |
|------|------|
| 寫作原則 — 語調 | 規範「真實、像在跟同事說話」的語氣，允許口語轉折詞，要求術語首次出現時附解釋 |
| 寫作原則 — 結構 | 三段式：直接切入的開頭、`##` 分段的主體、具體行動的結尾 |
| 寫作原則 — 表格 | 要求每篇至少含 1 個表格；列出 4 種適合用表格的情境 |
| 寫作原則 — 長度 | 字數範圍 1000–2000，複雜主題建議拆系列文章 |
| 文章模板 | Markdown 結構模板，含標題、開頭、主體段落、下一步 |
| 輸出格式 | Markdown（預設）vs HTML（含完整 CSS 規格） |
| 常見主題寫作提示 | AI 工具教學、技術導入指南的具體切入建議 |
| 品質檢查清單 | 7 項 checklist，寫完後自我驗證 |

#### `evals/evals.json`

**功能**：提供 3 個評測案例，覆蓋 skill 的主要使用情境。

| eval id | 主題 | 文章類型 |
|---------|------|---------|
| 1 | 公司導入 Claude 作為日常 AI 助手 | 技術導入指南 |
| 2 | 用 ChatGPT 整理會議記錄 | AI 工具教學 |
| 3 | 解釋什麼是 RAG | 概念科普 |

所有案例都要求同時產出 `.md` 和 `.html` 格式，預期輸出為 1000–2000 字、含表格、語調親切的繁體中文文章。

## 使用指南

### 快速開始

**場景 1：AI 工具教學**

```
使用者說：「寫一篇教同事用 ChatGPT 整理會議記錄的教學文章」

Claude 會執行：
1. 判斷主題屬於「AI 工具教學」類型
2. 套用 AI 工具教學寫作提示：從具體場景切入（會議記錄場景）
3. 產出包含操作步驟、prompt 範例的 1000-2000 字文章
4. 至少包含 1 個表格（例如：功能對比或步驟整理）
5. 結尾給出具體行動建議（例如：「下次開完會就試試這個流程」）
6. 輸出：預設 .md 檔案
```

**場景 2：技術導入指南（雙格式輸出）**

```
使用者說：「幫我寫一篇公司導入 Claude 的指南，同時產出 md 和 html 兩種格式，存到 outputs 資料夾」

Claude 會執行：
1. 判斷主題屬於「技術導入指南」類型
2. 套用導入指南寫作提示：導入前後對比表格、前置條件、分階段建議
3. 產出 1000-2000 字文章，含導入前後差異表格
4. 同時產出 outputs/article.md（或對應名稱）
5. 產出 outputs/article.html（含 800px 置中、響應式 CSS、表格交替底色）
```

**場景 3：概念科普**

```
使用者說：「幫我寫一篇科普文章解釋什麼是 RAG，讓不懂 AI 的同事也能看懂」

Claude 會執行：
1. 判斷主題為「概念科普」
2. 以生活化比喻解釋 RAG（Retrieval-Augmented Generation）
3. 首次出現技術術語時附上簡短解釋
4. 用表格整理 RAG 有無差異對比
5. 結尾建議讀者下一步可以做什麼（例如：「問問你的 AI 專案負責人…」）
```

### 輸出格式控制

```
# 只要 Markdown（預設）
「幫我寫一篇關於 XXX 的文章」

# 只要 HTML
「幫我寫一篇關於 XXX 的文章，輸出 HTML 格式」

# 兩種都要
「幫我寫一篇關於 XXX 的文章，同時產出 md 和 html 兩種格式」
```

### HTML 輸出的 CSS 規格

當要求 HTML 輸出時，會自動套用以下樣式：

| CSS 屬性 | 值 | 說明 |
|---------|-----|------|
| 字體 | `-apple-system, "Microsoft JhengHei", sans-serif` | 跨平台顯示中文 |
| 行距 | `1.8` | 提高繁體中文可讀性 |
| 最大寬度 | `800px` | 避免寬螢幕行太長 |
| 表格 | 邊框 + 交替行底色 | 方便掃描比較 |
| 響應式 | 是 | 手機也能閱讀 |

### 使用技巧

- **直接給具體主題**：說「幫我寫一篇關於公司導入 Copilot 的指南」比「幫我寫科技文章」效果更好，Claude 能直接套用對應的寫作提示。
- **指定存放路徑**：說「存到 outputs 資料夾」，Claude 會自動建立對應目錄並寫入檔案。
- **善用「兩種都要」**：如果要在內部平台發布，先用 HTML 確認排版，再用 Markdown 版本存檔。
- **系列文章**：若主題複雜，可以說「幫我規劃一個 3 篇的系列文章，先寫第一篇」，skill 會自動控制單篇字數在範圍內。

## 開發者指南

### 如何擴充這個 Skill

#### 新增文章類型

目前 SKILL.md 只有「AI 工具教學」和「技術導入指南」兩種具體的寫作提示。要新增其他類型（例如：事故復盤報告、產品發布公告），需要修改：

```
想要新增「事故復盤報告」文章類型時，需要修改：
1. SKILL.md → 在「常見主題的寫作提示」章節補充新類型的指引
   - 說明讀者最想知道的問題
   - 給出具體的切入角度
   - 列出這類文章常用的表格格式
2. evals/evals.json → 新增對應的評測案例以驗證品質
```

#### 修改觸發條件

SKILL.md 的 `description` 欄位控制 Claude 何時使用這個 skill：

```yaml
description: >
  撰寫繁體中文科技文章，專為企業內部同事快速閱讀而設計。適用於 AI 工具教學、技術導入指南、科技概念科普等主題。
  當使用者提到要寫科技文章、AI 教學文、技術導入指南、內部技術通訊、幫同事解釋某個 AI 工具或技術概念時，
  # 在這裡補充新的觸發情境，例如：
  # 也適用於月度技術簡報、技術演講摘要等。
```

#### 修改 HTML 樣式

HTML 輸出的 CSS 規格定義在 SKILL.md 的「輸出格式」章節。若公司有統一的字體或配色規範，直接修改該章節的 CSS 屬性說明即可。

### 設計決策記錄

| 決策 | 選擇 | 原因 |
|------|------|------|
| 字數範圍 | 1000–2000 字 | 夠讓忙碌同事願意讀完，也夠把事情說清楚；複雜主題建議拆系列而非拉長單篇 |
| 輸出格式預設 | Markdown | 適合版本控制與多平台轉換；HTML 作為可選項供排版需求使用 |
| 語言規範 | 繁體中文 + 口語化語調 | 針對企業內部溝通；避免學術腔增加閱讀門檻 |
| 表格強制要求 | 至少 1 個 | 忙碌讀者習慣掃描式閱讀，表格是最有效的資訊壓縮格式 |
| 無外部腳本 | 純 SKILL.md 設計 | 降低使用門檻，不需安裝任何套件或設定環境變數 |

### 測試方式

使用 `evals/evals.json` 中的 3 個案例驗證 skill 輸出：

1. **eval 1（技術導入指南）**：產出應包含導入前後對比表格、分階段建議、.md 和 .html 兩個檔案
2. **eval 2（AI 工具教學）**：產出應從具體會議場景切入、含操作步驟、附 prompt 範例
3. **eval 3（概念科普）**：產出應用生活化語言解釋 RAG、術語有解釋、非技術讀者可理解

每次修改 SKILL.md 後，用以上 3 個 prompt 重新執行，確認：
- 字數在 1000–2000 範圍內
- 確實包含至少 1 個表格
- 語調符合「與同事說話」的標準（非論文腔）
- HTML 版本的排版在瀏覽器中正確顯示

## 注意事項與常見問題

### 已知限制

- **無法自動抓取最新資訊**：文章內容完全由 Claude 依訓練知識生成，不會即時搜尋網路。如果需要最新的工具版本或功能，使用者應在觸發語句中補充最新資訊。
- **HTML 樣式為內嵌 CSS**：不支援外部樣式表引用，無法與公司 CMS 的全域樣式整合（需人工調整）。
- **字數為估算**：Claude 的字數計算是估算值，實際輸出可能有 ±10% 的差距。

### 常見錯誤

| 問題狀況 | 原因 | 解決方法 |
|---------|------|---------|
| 文章語調偏學術、過於正式 | 主題描述太抽象，Claude 預設進入「說明文」模式 | 在觸發語句中加入「給不懂技術的同事看」或「像跟朋友解釋一樣」 |
| 沒有表格 | 主題不明顯有比較需求 | 在觸發語句中加「請包含比較表格」或指定「比較 A 和 B 的差異」 |
| 字數超過 2000 字 | 主題太複雜、Claude 試圖一次說完 | 改為「幫我規劃系列文章，先寫第一篇，聚焦在 XXX」 |
| HTML 排版在舊瀏覽器跑版 | 使用了 CSS flexbox / grid（現代語法） | 在觸發語句中加「使用傳統 CSS，不用 flexbox」 |
| 未同時輸出 md 和 html | 使用者只說「輸出兩種格式」但沒有說清楚 | 明確說「同時產出 .md 和 .html 兩個檔案」 |

### 安全注意事項

此 skill 純為文章生成工具，不涉及 API 金鑰或敏感資料。若文章主題涉及公司內部系統細節（如 API endpoint、內部服務架構），請在發布前確認文章內容符合公司資訊安全規範。
