# PRD 品質檢查清單

寫檔前必須逐項驗證，任一項 ❌ 就回對應 Phase 補問。

## 元資料完整性
- [ ] `title` 一句話可讀，不超過 30 字
- [ ] `prd_id` 符合 `PRD-YYYY-NNN` 格式且未重複
- [ ] `owner` 具名（不是「PM」）
- [ ] `stakeholders` 至少列 2 人
- [ ] `target_release` 有具體季度或日期（可以 TBD 但要標註）

## 背景與目標
- [ ] 痛點描述引用具體情境或數據，不是「體驗不好」這種空話
- [ ] 至少一條目標是 SMART（有數字、有時限）
- [ ] 不做的影響有量化（人數 / 時間 / 金額擇一）

## 目標 / 非目標
- [ ] 非目標至少 2 條
- [ ] 非目標有明確排除 scope（例：「不含 mobile」、「不改既有權限模型」）

## 使用者
- [ ] persona 表格至少 1 列
- [ ] 痛點與期望結果分開填寫（不是同一句話）

## 功能需求
- [ ] 每條 FR 有唯一編號
- [ ] 每條 FR 有優先級（P0/P1/P2）
- [ ] **每條 FR 至少一條 AC**
- [ ] **每條 AC 用 Given/When/Then 格式**
- [ ] AC 的 Then 子句是可觀察結果（非實作細節）
- [ ] 有依賴的 FR 有標出依賴項

## NFR
- [ ] 效能欄位有具體數字或 N/A
- [ ] 安全欄位有說明或明確 N/A（不可空白）

## 風險
- [ ] 每條風險有 owner 和 due date
- [ ] 「未決事項」不超過 5 條（超過代表 PRD 還不該定稿）

## 整體
- [ ] 全文不含「之後再補」、「TODO」未指派
- [ ] 沒有 copy-paste 殘留的 {{PLACEHOLDER}}
