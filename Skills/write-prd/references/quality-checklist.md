# PRD 品質檢查清單

完成 PRD 後，以四個角色視角進行檢查：

## 1. 技術負責人視角 🔧

從技術實現難度、系統效能、安全風險角度審視：

### 檢查問題
- [ ] 並發處理：高峰期如何保證系統穩定？
- [ ] 冪等性：重複提交如何處理？
- [ ] 異常恢復：網路斷開、支付中斷如何處理？
- [ ] 資料一致性：分散式場景下如何保證？
- [ ] 安全防護：SQL注入、XSS、CSRF如何防範？
- [ ] 效能瓶頸：大數據量查詢如何優化？

### 範例問題
> 「如果用戶在支付過程中網路斷開，訂單狀態如何處理？是否有冪等性設計？」

---

## 2. 挑剔用戶視角 👤

從操作便捷性、流程合理性角度審視：

### 檢查問題
- [ ] 操作步驟是否過多？能否減少點擊次數？
- [ ] 表單欄位是否過多？能否智慧填充？
- [ ] 錯誤提示是否友善？用戶能否理解？
- [ ] 載入狀態是否清晰？用戶是否知道在等待？
- [ ] 撤銷/回退是否方便？

### 範例問題
> 「為什麼修改收貨地址要跳轉三個頁面？能不能在訂單確認頁直接編輯？」

---

## 3. 營運負責人視角 📊

從數據分析、營銷推廣角度審視：

### 檢查問題
- [ ] 埋點設計：關鍵行為是否有埋點？
- [ ] 轉化追蹤：營銷活動效果如何評估？
- [ ] 用戶分層：如何區分不同價值用戶？
- [ ] 營運工具：是否有足夠的後台設定能力？
- [ ] 資料匯出：營運報表如何生成？

### 範例問題
> 「是否有用戶行為埋點？如何追蹤營銷活動的轉化效果？」

---

## 4. 測試工程師視角 🧪

從異常場景覆蓋角度審視：

### 檢查問題
- [ ] 邊界值：最大/最小/空值如何處理？
- [ ] 並發操作：多人同時操作同一資料？
- [ ] 網路異常：弱網、斷網、超時？
- [ ] 裝置兼容：不同螢幕、瀏覽器、系統？
- [ ] 權限邊界：越權操作是否被攔截？

### 範例問題
> 「如果用戶重複點擊提交按鈕會怎樣？是否有防重複提交機制？」

---

---

## 5. 原型 UI 品質檢查 🎨

交付原型前驗證：

### 視覺品質
- [ ] 不使用 emoji 作為圖示（使用 SVG）
- [ ] 所有圖示來自統一圖示庫（Heroicons/Lucide）
- [ ] Hover 狀態不會導致佈局偏移
- [ ] 使用語意化主題色（`bg-primary`）

### 互動
- [ ] 所有可點擊元素有 `cursor-pointer`
- [ ] Hover 狀態提供清晰視覺回饋
- [ ] 過渡動畫平滑（150-300ms）
- [ ] 鍵盤導航時焦點狀態可見

### 亮/暗模式
- [ ] 亮色模式文字有足夠對比度（4.5:1 最低）
- [ ] 玻璃/透明元素在亮色模式下可見
- [ ] 邊框在兩種模式下都可見

### 無障礙
- [ ] 所有圖片有 alt 文字
- [ ] 表單輸入有 label
- [ ] 顏色不是唯一的指示器
- [ ] 尊重 `prefers-reduced-motion`
