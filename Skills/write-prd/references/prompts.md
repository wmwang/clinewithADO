# 需求采集 Prompt 模板

## Prompt 1：從會議記錄提取需求

```
角色設定：
你是一位擁有 10 年經驗的資深產品經理，擅長從混亂的會議討論中提煉出清晰的業務需求。

任務背景：
我剛剛參加了一場產品需求討論會議，會議錄音已轉為文字。現在需要你幫我從中提取出可落地的功能需求清單。

輸入材料：
- 會議轉寫文稿（見上文）
- 項目背景補充：[在此貼上：目標用戶、業務場景、技術棧限制等]

輸出要求：
1. **內容清洗**：去除所有寒暄、跑題、重複內容，只保留與產品功能相關的需求描述
2. **結構分類**：按以下維度組織需求
   - 【核心業務流程】：端到端的主流程（如：用戶註冊→登入→下單→支付）
   - 【用戶端功能】：C端用戶可見的功能模組
   - 【管理端功能】：B端/營運後台功能
   - 【技術需求】：效能、安全、兼容性等非功能性需求
3. **優先級標注**：用 🔴 P0（必須有）/ 🟡 P1（重要）/ 🟢 P2（優化項）標記
4. **痛點標記**：用 ⚠️ 標注客戶反覆強調或情緒激動時提到的需求
5. **格式規範**：使用 Markdown 無序列表，每個功能一行

範例輸出格式：
## 核心業務流程
- 🔴 P0 用戶註冊流程：支援手機號+驗證碼註冊，需校驗手機號真實性
- 🔴 P0 ⚠️ 快速下單：客戶強調必須 3 步內完成下單，不能有繁瑣表單
```

## Prompt 2：結構化梳理 Feature List

```
角色設定：
你是一位擁有 B端/C端雙重經驗的產品架構師，擅長將零散需求整理為完整的功能地圖。

任務：
我正在規劃一個 [項目類型：如 SaaS CRM 系統 / 電商小程式 / 線上教育平台]，以下是大綱需求清單：
[貼上需求清單]

輸出要求：
1. **模組化劃分**：按業務模組組織（範例：帳號體系、首頁、商品管理、訂單流程、支付結算、個人中心、營運後台）
2. **功能三要素**：每個功能點必須包含
   - 功能名稱：簡潔明確，動賓結構（如：建立訂單、匯出報表）
   - 功能描述：用一句話說清楚「用戶可以做什麼」（WHO + DO WHAT + FOR WHAT）
   - 優先級：P0（MVP 必須）/ P1（重要增強）/ P2（體驗優化）
3. **邏輯完整性檢查**：主動指出需求中可能缺失的環節，例如：
   - 有「加入購物車」但沒提「購物車編輯/刪除」
   - 有「用戶註冊」但沒提「找回密碼」
   - 有「生成訂單」但沒提「訂單取消/退款」流程
4. **表格化輸出**：使用 Markdown 表格格式

輸出格式範例：
## 模組 1：用戶帳號體系
| 功能編號 | 功能名稱 | 功能描述 | 優先級 | 備註 |
|---------|---------|---------|--------|------|
| U-01 | 手機號註冊 | 用戶通過手機號+驗證碼完成帳號註冊 | P0 | 需防刷機制 |
```

## Prompt 3：反向推演（四角色審查）

```
角色切換指令：
現在請切換為以下四個角色，分別對上述 Feature List 進行「挑刺」：

1. **技術負責人**：從技術實現難度、系統效能、安全風險角度提出 3 個尖銳問題
   範例：「如果用戶在支付過程中網路斷開，訂單狀態如何處理？是否有冪等性設計？」

2. **挑剔的用戶**：從操作便捷性、流程合理性角度提出 3 個質疑
   範例：「為什麼修改收貨地址要跳轉三個頁面？能不能在訂單確認頁直接編輯？」

3. **營運負責人**：從數據分析、營銷推廣角度提出 2 個需求補充
   範例：「是否有用戶行為埋點？如何追蹤營銷活動的轉化效果？」

4. **測試工程師**：從異常場景覆蓋角度提出 2 個邊界問題
   範例：「如果用戶重複點擊提交按鈕會怎樣？是否有防重複提交機制？」

輸出格式：
- 每個角色的問題單獨列出
- 每個問題後面給出建議解決方案
- 標注哪些問題需要補充到 Feature List 中
```
